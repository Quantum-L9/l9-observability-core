# Repository Invariants - l9-observability-core

This file is the root invariant and enforcement index for the repository. It is derived from the
current repository tree and does not replace the semantic authorities under `docs/` or the wire
contracts under `schemas/v1/`.

Documentation snapshot: 2026-08-25, `l9-update-agent-docs` v2.0.2 from
`Quantum-L9/Cursor-Governance@829f45ec0ac8e1250878e4d8e96a0643ae7412c9`.

## Product invariants

1. `l9-observability-core` is a backend-neutral Python utility library.
2. It must not become an HTTP or MCP service, Constellation node, collector, exporter, storage
   system, logging configuration owner, deployment runtime, or organization CI orchestrator.
3. Semantic meaning is owned by the domain documents named in `AGENTS.md`; published wire shape is
   owned by `schemas/v1/*.json`. A conflict between them is a stop-and-reconcile condition.
4. Canonicalization, digesting, timing, correlation, and cross-event validation remain deterministic
   and side-effect free.
5. Producer-supplied identifiers and timestamps are validated, not silently generated.
6. The public v1 wire contract is not weakened to make tests or tooling green.
7. Fixture, helper, schema, and package success are not evidence of runtime integration.
8. `event_digest()` is exact canonical content identity, not exactly-once delivery or logical-operation deduplication.
9. An evidence digest binds expected content identity; it does not by itself prove durable retrievability.
10. Relational validators are applied explicitly at the consumer/admission boundary whose semantics they validate.

## Repository execution invariants

1. `Makefile` remains byte-identical to `tools/l9_repo/Makefile.template`.
2. Product-specific repository targets live in `Repo.mk`.
3. `.l9/repo-workflow.json` is the local repository-execution contract and `tools/l9_repo/` executes
   it.
4. Organization CI execution remains externally owned. This repository intentionally contains zero
   files under `.github/workflows/`.
5. There is no `.pre-commit-config.yaml`; therefore the repository has zero declared pre-commit
   hooks and agents must not claim local hook coverage.
6. `uv lock --check` is part of the push/pre-PR safety contract when a valid `uv.lock` is available.
7. Missing external tooling is reported as blocked evidence, never converted into a synthetic pass.
